# 扣子工作流接入说明（真正的 RAG 版）

这套是**完整 RAG 架构**：资产存在扣子知识库里，多模态节点输出的 `query` 去检索，打分节点**只处理召回的资产**——代码里不含任何资产数据，资产增减只改知识库，不用动代码。

按下面 5 步改，工作流就能跑出正确结果。配套的 `.py` / `.txt` 文件都在本目录，可整段复制粘贴。

---

## 先搞懂：为什么必须是这个架构

扣子知识库检索节点的输出是固定的：一个 `outputList` 数组，每项只有 `output`（召回的文本）和 `documentId`。**它返回的是文本，不是结构化字段**。

所以要做两件事：
1. **知识库里每条资产存成一行完整 JSON**——这样召回的 `output` 就是这条 JSON，能被代码解析出面数、贴图、价格这些数字。
2. **打分节点从召回文本里解析 JSON 再打分**——只处理召回的候选，不去遍历全库。

这就是 RAG 和"内嵌全库"的本质区别：内嵌版资产写死在代码里，加一个资产要改代码；RAG 版资产在知识库，加资产只需往知识库传一条。

---

## 第 1 步：把 26 个资产导进扣子知识库

用本目录新生成的 **`mita3d-kb.txt`**（RAG 专用）：

- 每行是一条资产的**完整 JSON**（含名称/品类/风格/颜色/面数/贴图/价格/授权等全部字段）
- 每行末尾有 `search_text` 字段（名称+品类+标签+描述拼成的检索文本），提升语义召回命中率
- 26 条之间用**空行**分隔，方便按段落切成 26 个片段

**操作**：
1. 扣子 → 资源库 → 知识库 → 新建 → 上传 `mita3d-kb.txt`
2. 切片方式选「按段落 / 自定义分隔符=空行」，确保**一条资产 = 一个切片**
3. 等待解析完成

> 关键：必须让一条资产对应一个召回片段。如果切片把两条 JSON 切到一起，代码里的括号匹配解析仍能拆出多条，但语义召回精度会下降。

其它格式 `mita3d-assets.csv` / `.json` 仍保留，供留档和二次开发；**RAG 导入只用 `mita3d-kb.txt`**。

## 第 2 步：多模态解析节点改成结构化输出

**① 系统提示词**：粘贴 `结构化输出Prompt.txt` 全部内容。

**② 打开「输出格式 = JSON」，导入的是「JSON 样例」，不是 JSON Schema（关键！）**：

扣子官方文档明确：输出格式 JSON 时，导入的是一段**带示例值的 JSON 样例**，系统照样例的结构自动生成 7 个输出参数。**不要导入带 `type`/`properties`/`description` 的 JSON Schema**——那样扣子会把 `type`/`properties`/`required` 当成字段名，模型会把 description 文本当值照抄（现象：检索节点收到 `按主体组合的检索词串...` 这种文字，输出区出现 `type: "object"`）。

导入这份**样例**（值是真实示例，不是类型说明）：

```json
{
  "category": "动物",
  "style": "写实",
  "color": "灰/黑",
  "subject": "犀牛",
  "keywords": ["犀牛", "动物", "写实", "灰黑", "摆件"],
  "query": "犀牛 动物 写实 灰黑 摆件",
  "summary": "一只写实风格的灰色犀牛摆件"
}
```

导入后扣子会自动生成 7 个平级输出参数：`category`/`style`/`color`/`subject`/`keywords`(Array)/`query`/`summary`，**顶层直接就是这 7 个，不应有 `properties` 这一层**。如果输出区显示 `type`/`properties`/`required` 或 `输出 → properties → category...`，说明贴成了 Schema，删掉重贴上面的样例。

> 取值范围的选项约束（动物/写实/灰黑 等）已经写在 `结构化输出Prompt.txt` 的系统提示词里，不靠 JSON 框表达，所以这里放心用示例值。

**③ 输出去向**：
- `query` → 接「知识库检索」节点的 `Query`（这就是 RAG 的检索输入，补上你截图里空着的那根线）
- **整个输出对象** → 接下一步节点B 的 `intent`（打分要的字段都在里面）

> 模型选**豆包系列**（支持视觉理解、不输出思维链）。别选 DeepSeek-R1 这类推理模型，它会夹带 `reasoning_content` 污染下游。

**④ 图片必须绑到「视觉理解输入」**：光在提示词里写 `{{image}}` 不够。在节点配置里找到「**视觉理解输入**」→ 点 `+` → 选 `image` 变量（类型选**图片/Image**，不是 String）。如果这一栏是空的，模型看不到图，输出的 7 个字段就全是 null/空。

**⑤ 两个"看起来没输出"的正常现象，别误判**：
- 节点配置面板的「输出」区显示的是**结构定义**（字段名+类型），本来就不显示识别值；真实值在节点运行后的「运行结果」里看。
- 结果区字段旁的数字（如 `category (2)`、`required (7)`）是**字符数/元素个数**，不是分数。

> 排查顺序建议：先看「运行结果」里 7 个字段有没有真实值 → 再核对输出格式框贴的是**样例**而非 Schema → 最后确认 image 已绑到视觉理解输入。

## 第 3 步：配置「知识库检索」节点

- 输入 `Query` → 引用「多模态需求解析」的 `query`
- 知识库 → 选第 1 步建好的那个
- **最大召回数量建议 10**（召回太少，后面打分过滤后可能没几个）
- 最小匹配度 0.5 左右即可；搜索策略用默认的「混合」
- 输出 `outputList` → 接节点B 的 `recalled`

> **召回为空别急着改配置**：先核对检索词指向的东西库里有没有。这 26 个资产里动物类只有猞猁/犀牛/新袋熊/鸟/浣熊/狗屋动物/恐龙/珊瑚礁，**没有牦牛、猫、马**等。若草图被识别成库里没有的品类，`outputList` 为空是正确行为，由第 5 步空结果分支兜底。验证方法：把 Query 手动改成 `犀牛 动物 写实` 跑一次，若有召回则节点配置无误。只有"库里确实有、但仍召回为空"时才调低最小匹配度到 0.3~0.5。

---

## 第 4 步：两个打分节点合并成一个代码节点 B

删掉原来的「规则过滤和打分」「综合评估和排序」两个大模型节点，换成**一个代码节点**：

- 节点名：`确定性打分（RAG）`，类型「代码」，语言 Python
- 代码：把 `节点B-确定性打分.py` 全部贴进去（**不含任何资产数据**，只处理召回结果）
- **输入参数**：

  | 参数名 | 类型 | 引用 | 说明 |
  |---|---|---|---|
  | `intent` | Object | 「多模态需求解析」整个输出对象 | 结构化意图（也兼容 JSON 字符串） |
  | `recalled` | Array | 「知识库检索」的 `outputList` | 召回的资产候选 |
  | `engine` | String | 「开始」的 `engine` | 决定分辨率标准 |
  | `budget` | Number | 「开始」的 `budget` | 超预算降权标注 |

  > `intent` 引用整个输出对象；`recalled` 引用 outputList 数组。两者类型别选错。

- **输出参数（手动配置，没有「同步」按钮）**：
  1. 先把默认的 `key2` 那行删掉（点行尾的删除图标）
  2. 点「输出」右侧的 `+`，依次添加 4 个参数，**名字和类型必须和代码 return 的对象完全一致**：

  | 参数名 | 变量类型 | 对应代码里的值 |
  |---|---|---|
  | `results` | String | `json.dumps(top)`，JSON 字符串 |
  | `summary` | String | 一句话推荐文案 |
  | `count` | Number（数字/整数） | Top N 数量 |
  | `topOne` | String | 排第一的资产名 |

  > 扣子新版（2025-09-16 升级后）的代码节点做了简化：节点输出区**没有「同步」按钮**，只能手动加参数。旧教程里的「同步 / 更新 Schema」在 **IDE 里**：点代码区右上角「在 IDE 中编辑」→ 点「测试代码」跑一次 → 在测试面板的「原始输出」上点「同步到节点」。两种路径结果一样，手动加最稳。
  >
  > **`count` 一定选数字类型**，否则下一步「选择器 count > 0」会失效。

  > 节点B 已内置 `normalize_asset`，能兼容扣子知识库召回时的"文本化 JSON"：数值是字符串（`"polygons":"64000"`）、数组变 `a|b|c`（`"tags":"犀牛|动物"`）、缺 `texture` 字段——都会自动归一化。**不用你改知识库格式**，直接贴代码即可。若仍报 `str/int` 类型错误，说明贴的是旧版代码，重新贴当前 `节点B-确定性打分.py`。

**代码内部流程**：
1. 从 `recalled` 每条 `output` 里解析资产 JSON（容忍 markdown 代码块、前后缀文字，自动去重），并归一化文本化字段类型
2. 对召回的资产打分：兼容 = 品类42%+风格26%+色彩20%+关键词12%；分辨率 = 贴图42%+面数40%+PBR/LOD 加成；价格 = 折扣62%+评分20%+基准18%；综合 = 兼容46%+分辨率30%+价格24%
3. `engine` 调整分辨率标准、`budget` 给超预算资产降权
4. 相关性过滤，剔除不相干资产，按综合分排序取前 5

已实测 5 个场景：标准召回、带代码块的脏文本、重复去重、空召回、预算降权——全部通过。

## 第 5 步：「检索结果为空」判断分支

**位置：在「确定性打分」之后、「top5 组装 / 回复」之前。**

加一个「选择器」节点，输入变量选节点B 的 `count`：

| 分支 | 条件 | 连到 |
|---|---|---|
| 分支 1（有结果） | `count` 大于 `0` | 走「组装结果 → 回复」，展示 `results` / `summary` |
| 分支 2（无结果/默认） | 否则 | 连「文本输出」节点：`没有找到合适的资产，试试放宽关键词或预算。` |

> 放在打分后最准：召回有东西但打分后全被过滤的情况也能兜住。节点B 空结果时已生成友好文案，可直接用。

### 「组装结果」节点怎么写（代码节点 C）

有结果分支里，别再让大模型重新组织语言（费 token 还会改数），用**一个代码节点**把 `results` 拼成 Markdown 即可。代码在 **`节点C-结果组装.py`**，整段贴进一个 Python 代码节点：

- **输入参数**（手动添加 4 个，全部引用节点B 的输出）：

  | 参数名 | 类型 | 引用 |
  |---|---|---|
  | `results` | String | 节点B 的 `results` |
  | `summary` | String | 节点B 的 `summary` |
  | `count` | Number | 节点B 的 `count` |
  | `topOne` | String | 节点B 的 `topOne` |

- **输出参数**（手动添加 1 个）：`text`（String）。

它输出的 `text` 是一段 Markdown（标题 + 一句话结论 + Top5 每个资产的兼容性/画质/价格、价格授权、推荐理由），直接接到**回复节点**引用 `text` 就行。文案逻辑跟前端原型一致，分辨率/价格是估算值也照实标注了。

> 如果嫌麻烦，也可以跳过节点 C，让回复节点直接引用 `summary`（只有一句话结论）+ `results`（JSON），但展示效果差很多。建议用节点 C。

## 最终工作流长这样

```
开始(image/query/budget/engine)
   ↓
选择器：image 或 query 非空？ ──否──→ 提示「请上传图片或填写需求」→ 结束
   ↓是
多模态需求解析（JSON 输出 7 字段 + 上面的 Prompt）
   ├─ query ─────────→ [知识库检索]（mita3d-kb.txt）── outputList ─┐
   └─ 整个输出对象 ────────────────────────────────────────────┤
                                        engine/budget ← 开始 ───┤
                                               ↓               ↓
                                      [代码节点B] 确定性打分（RAG）
                                               ↓ (results, count, summary)
                                       [选择器] count > 0 ?
                                         ├─是─→ [代码节点C 组装结果] → text → 回复
                                         └─否─→ 「没找到合适资产」→ 结束
```

整条链是标准 RAG：**解析 → 检索 → 打分 → 判断 → 组装 → 回复**。资产全在知识库，代码零资产数据。

---

## 几个容易踩的坑

1. **知识库必须传 `mita3d-kb.txt`**（每行一条 JSON），不要用 CSV——CSV 召回的是表格文本，解析不出完整字段。
2. **一条资产 = 一个切片**：切片方式选对，否则召回片段含半条 JSON。
3. **召回数量设大些（10 左右）**：召回太少，打分过滤后可能没结果。
4. **代码节点语言选 Python**；输入参数名一字不差：`intent` / `recalled` / `engine` / `budget`。
5. **`recalled` 选 Array 类型**引用 outputList；`intent` 选 Object 引用整个输出对象。
6. **模型选豆包系列**，别用推理模型（会有思维链污染）。
7. `engine` 传中文（「静帧渲染/电商主图」）或英文 key（`render`）都行；`budget` 传纯数字，不带 `¥`。

## 数据边界（如实说明）

知识库里的 26 个资产：

- **站点核验字段**：名称、分类、价格、授权、文件大小、浏览/下载量、发布年份
- **演示估算字段**：面数、贴图分辨率、PBR、LOD、市场均价、评分（Mita3D 公开接口未提供）

用于演示和验证没问题；真要商用对接，这些估算值需换成平台正式数据。
