产品案例 / Portfolio

我的角色 · AI 产品经理：从问题定义、方案取舍到落地验证由我一人主导；我把技术边界与成本算进产品决策，方案可落地、预期可控。
做这件事的原因：买家手里往往只有一张参考图、一张草图，或一句模糊的想法。
但要回答的问题很具体：风格对不对？能不能用？值不值这个价？
Match3D Agent 把这三个问题，一次变成有依据的结论——从兼容性、画质、价格三个维度给出可解释评估与"买哪个"的结论。

目标与思路
三个决策问题① 风格对不对：参考图与候选是否匹配；② 能不能用：授权可否商用、画质够不够；③ 值不值：同类价差大缺基准。买家只有一张图或模糊想法，三个问题每次采购都要重答一遍。
产品思路多模态理解 → 相关性过滤 → 可解释评分 → 渐进披露 → 并排对比给结论；结论摆最前、证据按需展开；资产走知识库、不写死代码。核心标准：每个结论是否帮用户更快做决定，而非功能更炫。用户真正的难点不是"找不到"，而是"找到了也难以下决定"。
迭代优化记录（三个关键判断）
#问题性质怎么解决 → 结果
1草图解析不准，用描述里的名词纠正产品设计 草图潦草、主体常被认错，但用户手写的名词是明确意图 → 定规则：文字与图片冲突时，文字具体名词强制覆盖图片解析名词；再叠加两级锚点过滤（具体名词强锚点精确匹配＋泛类兜底＋停用词表）。搜犀牛仅返回犀牛，不再混入发动机、狗屋；识别成库里没有的品类也能靠文字纠正或友好返回空结果。一次错误推荐就会损害信任，相关性是底线。
2降本：不牺牲效果，控制 token 成本工程优化 识别品类/风格/颜色/主体是轻量任务，用不上旗舰大模型 → 两头降本：图片侧裁白边→缩到512–1024→JPEG压缩，体积20KB→4KB；模型侧建议用轻量视觉模型——首选千问 Qwen3.7-Flash（支持图像理解＋JSON输出，输入约¥0.2/百万token），或智谱 GLM-4V（国产、中文强、同为厘级）。避开旗舰推理模型（贵10–50倍＋思维链污染结构化）和纯文本模型（如DeepSeek，不支持视觉）。−79%且识别不降；单次约万分之二元、1元跑数千次。
3海量资产，该不该做成数据库？架构决策 26个用知识库可验证，但海量资产文档库撑不住、也不擅长结构化过滤 → 判断是分层不是二选一：① 结构化字段（品类/价格/授权/面数）进 PostgreSQL 做精确过滤分面；② 名称+标签+描述做 embedding 进向量索引（pgvector/Milvus/ES）做语义召回；③ 先硬过滤缩小候选，再向量召回＋关键词BM25两路并行、融合重排后接确定性打分；④ 主库存源数据，向量索引可重建。几十万级用 PG+pgvector 一套够，百万级再上专用向量库；现在的 RAG+零内嵌就是最小验证版，换库不动打分逻辑。
早期迭代已收起：资产数据真实化（无头浏览器抓取，26/26 命中）· 对比决策摘要（平局灰显、授权一票否决）· 体验细节稳定性（26/26 图片正常）。
最终链路
① 多模态解析图/文字→结构化意图
② 知识库检索query 召回候选
③ 确定性打分过滤+评分+排序
④ 空结果判断有果/无果分支
⑤ 结果组装拼 Markdown
⑥ 回复给出结论

前端原型验证产品体验：草图解析＋文字名词纠正、渐进披露、并排决策、草图压缩 −79%，可上手点、离线也能演示。
扣子 RAG 工作流验证规模化落地：资产零内嵌、增减只改知识库、12 节点跑通、可发布 Bot/API。两者共享"理解→检索→打分→结论"逻辑；演示先放前端上手、再放工作流证明能落地。真产品化时前端改调工作流 API 即可对接。

商业化：按决策价值收费

① 嵌入式选品助手：给 3D 平台做助手，提升"搜索→购买"转化，按成交分成 / SaaS 年费（最快落地）。
② 通用决策 API：理解→召回→确定性打分→可解释结论，复制到家具/面料/工业件等非标品采购，按调用量收费。
③ 评分规则与标签资产：沉淀可迁移的行业 know-how 作壁垒。
前提：面数等为估算、26 个仅验证，RAG+零内嵌架构已为接真实大库预留扩展。

数据边界：售价、分类、体积、格式、热度、年份取自平台公开信息；面数、贴图分辨率、PBR、LOD、均价基准与评分因平台未公开为演示估算，界面以"估算"徽标区分。资产与图片已做离线快照，接口变更也能完整演示。
