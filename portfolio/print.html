目标与思路
三个决策问题① 风格对不对：参考图与候选是否匹配；② 能不能用：授权可否商用、画质够不够；③ 值不值：同类价差大缺基准。买家只有一张图或模糊想法，三个问题每次采购都要重答一遍。
产品思路多模态理解 → 相关性过滤 → 可解释评分 → 渐进披露 → 并排对比给结论；结论摆最前、证据按需展开；资产走知识库、不写死代码。核心标准：每句话是否帮用户更快做决定，而非功能更炫。真正卡住用户的不是"找不到"，而是"找到了不敢拍板"。
迭代优化记录（七个关键判断）
#问题性质怎么解决 → 结果
1演示资产是编的，没有说服力架构决策 站点是关闭 SSR 的 SPA，普通抓取拿不到数据 → 用无头浏览器渲染 DOM 再解析，拿到 26 个真实资产；关键词逐个搜内部接口、按图片尾号精确匹配 ID，26/26 命中，回填真实分类/体积/格式/热度。资产从"编的"变"真的"；未公开的面数等明确标估算。
2搜犀牛却混进发动机、狗屋、鸟产品设计 全量打分后不过滤，低分资产仍在 → 设计两级锚点：具体名词（犀牛/机甲）为强锚点只精确匹配，泛类（动物）为弱锚点兜底，加停用词表过滤无意义主体。搜犀牛只剩犀牛一条（兼容 93），结果可信。
3归因表全铺开，用户根本不看产品设计 四张归因表平铺、普通与专业用户同等对待 → 改渐进披露：首屏一句话结论＋一正一负提醒，完整归因收进折叠区，风险提示只列需留意项。各取所需，可解释但不强制阅读。
4对比表十几行全打星，等于没说产品设计 13 维里只有 3 行有区分度，全打★制造"各有优势"错觉 → 加决策摘要（可商用优先→综合分→同分区间价低），平局灰显、授权受限一票否决。从"看表格"变"得结论"。
5图片破裂＋评估要点显示成单字工程优化 图片破裂、评估要点显示成单字且全橙，看似样式、实为数据问题，不修则产品显粗糙 → 定位根因：图片路径依赖预览环境，改为内联、去掉目录依赖；要点数据结构错误（一次推入两元素），统一结构并逐一验证。26/26 图片正常、文案告警恢复。
6上传草图太费 token工程优化 草图白边多、分辨率高 → 裁白边→缩到 1024→JPEG 0.82 再送模型；评估过换便宜模型但纯前端直连会暴露 key、需后端代理，原型阶段不划算。体积 20KB→4KB（−79%），识别不降。
7落地扣子：不能因只有 26 个资产就内嵌架构决策 坚持标准 RAG：资产进知识库、多模态输出 query 检索、代码节点只打分，零内嵌、增减只改知识库。连排三坑：① 输出格式贴 Schema 非样例→模型照抄字段说明，改贴真实样例；② 召回 JSON 被文本化（数值变字符串）打除法报错→加类型归一化；③ 图未绑"视觉理解输入"→补绑定。12 节点全链路跑通。
最终链路
① 多模态解析图/文字→结构化意图
② 知识库检索query 召回候选

④ 空结果判断有果/无果分支
