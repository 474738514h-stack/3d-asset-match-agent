# 口语版项目讲述 · 三档（AI 产品经理 · 面试可直接说）

> 三档是同一个内核在不同时间预算下的取舍：
> - **1 分钟**：只讲定位 + 我的角色 + 结果，开口就点题。
> - **3 分钟**：完整"问题→判断→落地→结果"，主推版本。
> - **5 分钟**：展开关键判断、落地能力和商业化，用于深聊 / 终面。
>
> **讲述基调**：我是产品经理，主线是"我怎么看问题、怎么做取舍、怎么推动落地"。工作流只作为"我能落地"的证据。语速按正常中文 220–240 字/分钟估算。

---

## 一、1 分钟版（约 245 字 · 开场/时间紧）

我做这个项目，想解决的不是"帮人找个模型"，而是**帮人在不确定中快速做决策**。3D 资产采购里，风格对不对、能不能用、值不值这个价——这三个问题反复出现，但买家手上往往只有一张参考图甚至草图，只能一个个比对，很难判断。

作为产品经理，我主导三件事：定义对的问题、做对的取舍、推动真正落地。我把"找和比"收敛成一句话结论——用多模态理解需求、检索资产、按兼容性和画质和价格打分，最后给结论和可展开的理由。方案定下来后，我把它落成了一个可上手的前端原型，和一条可上线的智能工作流。

过程中我坚持了几个判断：草图识别不准就用描述里的名词纠正、结果要精准召回、降本要保住效果、海量资产要走分层架构。最终一条 12 节点的链路全链路跑通，上传草图就能拿到带解释的推荐。**我的体会是：产品经理的价值在判断和落地，不在功能堆了多少。**

---

## 二、3 分钟版（约 720 字 · 主推）

**（定位）** 先说这个项目在解决什么。它容易被理解成"一个智能搜索工具"，但那不是它最值钱的地方。搜索解决的是"找到东西"，可买家真正难的是找到了也**做不了决定**——风格到底对不对、能不能商用、这个价值不值。这三个问题在采购里反复出现，每次都要人去比对、去猜。所以我的目标是：**买家只给一张图、一句想法，系统直接给一个能落地的结论和理由**。它的本质是决策辅助，不是检索。这个定位决定了后面所有取舍——我的标准始终是"这个结论能不能帮用户更快做决定"。

**（我的角色）** 我是产品经理，这个项目从问题定义到落地验证由我一人主导。我主导三件事：定义对的问题、做对的取舍、推动真正落地。我清楚技术的能力边界和代价——比如为什么打分要用确定性规则而不是大模型自由发挥，因为决策场景里同一个输入必须给同一个分，可复现、可解释是底线；一次匹配大概消耗多少成本，所以我提前把草图压缩和模型选型做进方案。把技术边界算进产品决策，我定的方案才能落地，给的排期和成本预期也靠谱。

**（做法）** 方案是一条确定性的链：多模态理解图像和文字，检索候选资产，用固定规则从兼容性、画质、价格打分；最后不是罗列一堆分数，而是给结论、给提醒、把归因折叠起来按需展开。

**（关键判断）** 过程中花时间最多的是判断。草图交给视觉模型解析，关键词经常不理想——把犀牛认成别的东西很常见，用户却往往在描述框里写了准确的名词。我判断：用户明确写出来的比模型猜的可信，所以定了"文字具体名词强制覆盖图片解析名词"的规则，再叠加两级锚点过滤，做到精准召回。成本上，我把"识别品类风格颜色"这件轻量任务想清楚——不需要旗舰大模型，草图裁白边压缩降八成，再用千问 Flash 这类轻量视觉模型，单次识别成本压到万分之二元级别。最后落地，我坚持资产走知识库、逻辑与数据解耦，12 个节点全链路跑通。

**（落地与结果）** 最关键的是落地：我没有停在原型和方案，而是把方案落成了一条可上线的智能工作流——资产放知识库、逻辑与数据解耦。这里我坚持了一个重要判断：不能因为只有 26 个资产就写死进代码，资产一变就要返工；我坚持走知识库检索，并提前识别出落地中的几处风险、定好约束让实现绕开。最终上传草图就能拿到带解释的推荐，增减资产只改知识库、不动系统。

**（收尾）** 做完这个项目，我的体会是：**产品判断和工程判断要一起算**。产品经理的价值在判断力和落地力——收敛没人看的功能、坚持必要但更复杂的架构，并且能把它真正推动成能跑能上线的系统。

## 三、5 分钟版（约 1300 字 · 深聊/终面）

**（一、拔高问题）**
先说清楚这个项目的价值，因为它容易被当成"智能搜索"。但它最值钱的地方不是帮人找东西，而是**帮人在不确定中快速做决策**。3D 资产采购里反复有三个问题：风格对不对、能不能用、值不值这个价。买家手上往往只有一张参考图、一张手绘草图，甚至一句模糊想法，他要在一个个模型间比对风格、授权、价格，很难判断。我想做的是把这种不确定压缩掉：**买家只给一张图，系统直接给一个能落地的结论和理由**。这个定位决定了后面所有取舍——我的标准始终是"这个结论是不是帮用户更快做了决定"，而不是"这个功能是不是更炫"。

**（二、我的角色）**
我是产品经理，从问题定义、方案设计到落地验证由我一人推动。我主导三件事——定义对的问题、做对的取舍、推动真正落地。我清楚技术的能力边界和代价：为什么打分要用确定性规则而不是大模型——因为决策场景里同一个输入必须给同一个分，可复现、可解释是底线；为什么资产必须和逻辑解耦——因为资产一定会变；一次匹配大概消耗多少成本——所以我提前把草图压缩和模型选型做进流程。**把技术边界和成本算进产品决策，我定的方案才能落地、给的预期才靠谱。** 这是我和纯执行 PM 最大的区别。

**（三、方案链路）**
方案是一条确定性链，四个环节：多模态理解把图或文字解析成结构化的品类、风格、颜色、主体关键词；检索召回找候选；确定性打分从兼容性、画质、价格三维评估，兼容性又拆成品类、风格、色彩、关键词四个因子；最后结果呈现给结论、给提醒、把归因折叠按需展开。

**（四、关键判断，展开三个）**
真正花时间的是判断，我挑三个展开。

**第一个，草图解析不准怎么纠正。** 草图交给视觉模型解析，关键词经常不理想——潦草的主体容易被认错，比如识别成库里根本没有的牦牛。但用户在描述框里手写的名词，是明确的意图，比模型猜测更可信。我定了一条规则：**文字里点名的具体名词，强制覆盖图片解析出的名词**；再叠加两级锚点过滤——具体名词做强锚点精确匹配、泛类兜底、停用词滤噪。这样即使图片识别跑偏，只要用户写了准确描述，就能召回对的资产。精准召回这件事，一次错误推荐就会损害信任，所以是底线。

**第二个，怎么在不牺牲效果的前提下降本。** 多模态识别每次调用都要付费，草图白边多、分辨率高，直接送模型很费 token。但我想清楚一件事：这个任务只是"识别品类、风格、颜色、主体几个词"，是轻量的结构化提取，用不上旗舰大模型。所以两头降本——图片侧裁白边、缩放、压缩，体积降八成，视觉 token 随之大幅下降，识别反而更稳；模型侧我的建议是用轻量视觉模型就够，比如千问 Qwen3.7-Flash、智谱 GLM-4V 这类，支持 JSON 结构化输出、中文识别强、输入价格约每百万 token 几毛钱。要避开两类误选：旗舰推理模型贵十几倍还会输出思维链污染结果，纯文本模型又不支持视觉。算下来单次识别成本约万分之二元，1 块钱能跑几千次，规模化完全可控。**这就是把成本算进体验——不是一味压缩，而是把成本花在关键处。**

**第三个，海量资产该怎么做。** 26 个资产用扣子知识库验证逻辑没问题，但真实业务是几十万上百万个资产，文档型知识库撑不起海量、也不擅长结构化过滤。我的判断是不做二选一，而是分层：结构化字段（品类、价格、授权、面数）进关系数据库做精确过滤，资产的描述和标签做 embedding 进向量索引做语义召回；查询时先按硬条件过滤缩小候选，再向量召回和关键词精确匹配两路并行、融合重排，最后交给确定性打分。几十万级用 PostgreSQL 加 pgvector 一套就够，上百万再上专用向量库。主库存源数据，向量索引是可重建的副本。**现在这套 RAG 加资产零内嵌，就是这个架构的最小验证版——以后换库不用改打分逻辑。**

**（五、商业化）**
最后聊商业化。我的判断是：**按"决策价值"收费，而不是"工具功能"**。搜索工具只能收流量费，但一个帮企业缩短决策时间、避免错误采购的助手，是按价值定价的——一次选错模型的返工成本，往往就超过一套工具年费。三条路：第一，最快的是给 3D 资产平台做嵌入式选品助手，提升"搜索→购买"转化，按成交分成；第二，把"理解需求→召回→确定性打分→可解释结论"这套骨架产品化，复制到家具、面料、工业零件等非标品采购，按调用量收费；第三，沉淀评分规则和标签体系，形成难以复制的行业 know-how。诚实地说，真商用要接真实大库、打通真实数据——而我坚持的解耦架构，恰恰为这件事预留了扩展性。

**（六、收尾）**
做完这个项目，我的体会是：**产品经理的价值在判断力加落地力**——收敛没人看的功能、坚持必要但更复杂的架构、并且能把它真正推动成能跑能上线的系统。产品判断和工程判断要一起算，这是我做 AI 产品的重要认知。

## 记不住就用：骨架口诀

**定位**：不帮人找东西，帮人在不确定中做决策（风格对不对 / 能不能用 / 值不值）
**角色**：定义问题、做取舍、推动落地——把技术边界和成本算进产品决策，方案能落地、预期靠谱
**做法**：多模态理解 → 检索 → 确定性打分（可复现是底线）→ 结论 + 按需归因
**三判断**：文字名词纠正草图识别（精准召回）／降本靠压缩＋轻量模型（万分之二元一次）／海量资产走结构化＋向量混合检索
**落地**：两套形态（前端验体验 + 工作流验规模化），资产解耦零内嵌、12 节点跑通——这就是工程化思维
**生意**：按决策价值收费 → 嵌入平台分成 → 泛化 API → 沉淀规则壁垒

## 面试可能追问的应对

- **"你怎么保证方案落得了地？"**
  → 我把技术边界和代价想清楚了才定方案：数据逻辑解耦、成本前置、确定性可复现、风险提前识别。这个项目的 12 节点链路就是我推动落地的证据。

- **"这个和纯执行 PM 有什么区别？"**
  → 纯执行 PM 把需求文档交给工程就结束了；我从问题定义、架构取舍到落地验证全程推动，能识别出"资产不能写死""打分必须可复现""草图该用什么模型"这类关键约束，并把它变成工程可执行的要求。

- **"你怎么证明这是你做的？"**
  → 项目从命题、取舍到落地全链路都由我定义和推动，材料里有完整记录（README 的迭代优化记录、工作流截图、作品集），每条都能讲清"我当时为什么这么判断"。
